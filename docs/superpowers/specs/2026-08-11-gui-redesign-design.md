## 1. ที่มา

เจ้าของรีโปสั่ง "ออกแบบ GUI ใหม่ให้สวยงาม ใช้งานง่าย อ่านง่าย" · เมื่อถามว่าของเดิมกวนใจตรงไหน
คำตอบคือข้อเดียว: **"ดูจืด ๆ เหมือน template AI"**

⇒ ปัญหาไม่ใช่ information architecture (8 ส่วนดีอยู่แล้ว — ยืนยันแล้ว) และไม่ใช่มือถือ
**ปัญหาคือหน้าตาไม่มีคาแรกเตอร์** งานนี้จึงเป็นงานดีไซน์ ไม่ใช่งานจัดโครงใหม่

### สาเหตุรากที่วัดได้

รีโปมี **สีแบรนด์ที่เลือกมือไว้แล้ว 908 ชุด** (`tools/seeds.json` → `report-data.theme`)
แต่ของเดิมใช้แค่ gradient หัวรายงาน + accent ประปราย ⇒ **ทุกใบหน้าตาเหมือนกันหมด**
นั่นคือ "เหมือน template" ตามตัวอักษร — และแก้ได้ฟรีเพราะข้อมูลมีอยู่แล้ว

ทำ mockup จากรายงานจริง ข้อมูลจริง กราฟเดินได้จริง แล้วให้เจ้าของเลือก:

| โครง 8 ส่วน | แถบสรุปบนสุด · สลับลำดับ · การ์ดพับได้ · **ไม่เปลี่ยน** | **ไม่เปลี่ยน** |
| หน้าแรก | การ์ด · ตาราง · **ไทล์สี** | **ไทล์สี + view toggle** |

### ★ การกลับมติเรื่องขอบเขต (ต้องรู้)

ตอนถามขอบเขตครั้งแรก เจ้าของเลือก *"ออกแบบใหม่ทั้งหมด — เปลี่ยน markup + migrate 908 ไฟล์ด้วยสคริปต์"*
หลังทำ mockup พบว่า **ดีไซน์ที่เลือกทำได้ครบโดยไม่ต้องแตะไฟล์รายงานเลย** (CSS + inject ตอน build)
แจ้งแล้วและเจ้าของรับทราบ ⇒ **ยกเลิกการ migrate 908 ไฟล์** ผลลัพธ์เท่าเดิม ความเสี่ยงต่ำกว่ามาก

**Invariant ที่ตามมา:** รายงานทั้งเก่าและใหม่คงเป็น content-only ใน vocabulary ปัจจุบัน
โครงนำเสนอใหม่ทั้งหมด**ฉีดตอน build อย่างเดียว** — ห้ามให้ skeleton สร้างโครงคนละแบบกับไฟล์เดิม
(ไม่งั้นต้องดูแล markup 2 ทรงตลอดไป)

## 3. สถาปัตยกรรมสี — หัวใจของงานนี้

### 3.1 ปัญหา

ดีไซน์ที่เลือกต้องการโทนสีต่อหุ้นราว 8 ค่า (พื้นหน้า, พื้นการ์ดรอง, เส้น 2 ระดับ, พื้นชิป, เงา)
แต่ `theme` ในรายงานมีแค่ 11 ค่าที่เลือกมือไว้ · **ห้ามเพิ่ม field ลง report-data 908 ไฟล์**

### 3.2 ทางแก้ — derive ใน Node ตอน build

`build.js` เพิ่ม `deriveTheme(theme)` คำนวณจาก `accent` (A) และ `accentDark` (AD) แล้วคาย **hex ตรง ๆ**

> **นิยาม `mix(สี, p%, ฐาน)`** = ผสมเชิงเส้นต่อช่อง sRGB: `round(สี×p + ฐาน×(1−p))` แล้วคายเป็น hex
> (เท่ากับ `color-mix(in srgb, สี p%, ฐาน)` — แต่คำนวณใน Node ตอน build)

| token ใหม่ | สูตร | ใช้ทำอะไร |
|---|---|---|
| `--tint-bg` | mix(A, 7%, `#f4f5f7`) | พื้นหน้าเว็บ |
| `--tint-card` | mix(A, 4%, `#ffffff`) | พื้นผิวรอง (calc box, chip) |
| `--line` | mix(A, 14%, `#e6e8ec`) | เส้นขอบปกติ |
| `--line-2` | mix(A, 26%, `#d8dbe1`) | เส้นขอบเน้น |
| `--soft` | mix(A, 13%, `#ffffff`) | พื้นชิป/fv-box |
| `--shadow`, `--shadow-lg` | A ที่ alpha 12–18% | เงาย้อมสีแบรนด์ |

**ทำไม derive ใน Node ไม่ใช่ `color-mix()` ใน CSS:**
1. ไม่ต้องกังวลว่าเบราว์เซอร์รองรับไหม
2. เข้ากับ pattern เดิม (`fillTokens` / `__RD_*__`) ที่ `renderHead()` ใช้อยู่
3. **ตรวจ contrast ตอน build ได้** — ถ้าคำนวณในเบราว์เซอร์จะตรวจไม่ได้

token เดิมทั้ง 11 ตัว**คงไว้ครบ** — ของเก่ายังเติมได้เหมือนเดิม token ใหม่เป็นส่วนเพิ่ม

### 3.3 กฎ contrast (บังคับ)

> **ตัวหนังสือขาวอยู่บน `accentDark` เท่านั้น — ห้ามอยู่บน `accent` ดิบ**
> `accent` ดิบใช้ได้เฉพาะงานกราฟิก (เส้น, จุด, glow, ขอบซ้ายการ์ด, แท่ง marker)
> หรือเป็นพื้นที่มีตัวหนังสือ**สีเข้ม**ทับ

**วัดจริงกับทั้ง 908 ชุด (11 ส.ค. 2569):**

| คู่สี | ตก AA (<4.5:1) |
|---|---|
| `accentDark` บนขาว | **0 / 908** ✅ |
| `accent` ดิบ บนขาว | **386 / 908** ❌ (43%) |

⇒ กฎนี้ไม่ใช่ความระมัดระวังลอย ๆ — ถ้าพลาดจะพังจริง 386 ใบ
(mockup รอบแรกพลาดข้อนี้ที่ `.s-head .n` และ `.ta-btn.on` — แก้แล้วก่อนเข้า spec)
สอดคล้องกับคอมเมนต์เดิมที่ `_template/dashboard.css:65` ที่ระบุว่า accentDark การันตี ≥4.5 กับขาว

### 3.4 Gate — ขยาย E38

เพิ่มการตรวจที่วิ่งทุกรายงานตอน verify · **ตกข้อไหน = build error ห้าม push**:

| คู่ที่ต้องตรวจ | เกณฑ์ |
|---|---|
| ink `#14161c` บน `--tint-bg` | ≥ 4.5:1 |
| muted `#6b7280` บน `--tint-card` | ≥ 4.5:1 |
| `accentDark` บน `--soft` | ≥ 4.5:1 |
| ขาว บน `accentDark` | ≥ 4.5:1 |
| ขาว บน `--badge` / พื้นสีทุกจุดที่มีตัวอักษรขาว | ≥ 4.5:1 |

ตาม CLAUDE.md §8: แก้ check ต้องเพิ่มเคสใน `test/self-test.js` + `npm run test:self` ผ่าน
เคสที่ต้องมี: seed ที่ผ่าน, seed ที่ accent สว่างจนตก (เช่น `#af8a00`), seed ที่ accentDark ตก (สังเคราะห์)

## 4. หน้ารายงาน

### 4.1 ที่เปลี่ยน

- **ตัวอักษร:** Kanit (หัวเรื่อง/ตัวเลขเด่น) · Sarabun (เนื้อความ) · IBM Plex Mono (ตัวเลขตาราง)
  `FONT_LINKS` ใน `build.js` ต้องเพิ่ม Kanit
- **สีแบรนด์ลงทั้งหน้า** — พื้น, เลขหัวข้อ, เส้น, ปุ่ม, gauge, verdict ⇒ ZTS เขียว · ASK เขียวน้ำเงิน · FIVE บานเย็น
- **ราคาเป็นพระเอก** — 66px Kanit บนบล็อกสีแบรนด์
- **ไม่มีอีโมจิ** — 🐻/⚖️/🚀/🧮/💡/⚠️ ออกทั้งหมด (ตัวชี้ "AI template" ที่ดังที่สุด)
- **section nav แบบ sticky** — แก้ปัญหาหน้ายาว 4,400px
- **มือถือจริงจัง** — breakpoint 480 / 760 / 1024 (ของเดิมมีจุดเดียวที่ 760)

### 4.2 ที่ **ไม่** เปลี่ยน

- ลำดับและเนื้อหา 8 ส่วน
- ชื่อ class ทุกตัว (gate อ้างอิงตรง ๆ: `.chg` ×28, `.px` ×27, `.sub` ×16, `.gauge` ×16 …)
- id ที่ engine/กราฟใช้: `#priceChart` `#gbar` `#mCur` `#mFair` `#pxIn` `#mosOut` และ `.ta-*`
- ไฟล์ `reports/*.html` — **ไม่แตะแม้แต่ไฟล์เดียว**

### 4.3 การ inject ตอน build (`expandReport()`)

ของเดิม inject อยู่แล้ว: style, engine, votebar, OG meta, TA chart · **เพิ่ม 2 อย่าง**

1. **section nav** — สร้าง markup **แบบ static ตอน build** จาก `<h2>` ทั้ง 8
   ⇒ ใช้งานได้แม้ JS ปิด · ส่วน scroll-spy (ไฮไลต์ส่วนที่กำลังอ่าน) เป็น progressive enhancement
2. **ถอดอีโมจิ** — ทำกับสตริง HTML **ตอน build** ไม่ใช่ runtime

> ★ **ขอบเขตการถอดอีโมจิ — ต้องยิงเฉพาะช่องที่รู้จัก ห้าม regex กวาดทั้งเอกสาร**
> `build.js` ไม่มี DOM parser (ตั้งใจ — no dependency) ⇒ ทำงานบนสตริง
> ถ้ากวาดทั้งไฟล์จะกินอีโมจิที่ agent ตั้งใจใช้ใน prose ของ catalyst/risk/verdict ด้วย
> ยิงเฉพาะ 5 ช่องนี้ (ตำแหน่งตายตัวจาก skeleton):
> | ช่อง | ของเดิม |
> |---|---|
> | `.scn .top` ป้ายฉาก | `🐻 Bear` · `⚖️ Base` · `🚀 Bull` |
> | `.calc label` | `🧮 ลองคำนวณ…` |
> | `.zone` ต้นข้อความ | `💡 <b>กลยุทธ์:</b>` |
> | `.disc` ต้นข้อความ | `⚠️ <b>คำเตือน:</b>` |
> | `.s-head`/`.cr h3` (ถ้ามี) | ไอคอนประดับ |

> ★ ต่างจาก mockup: mockup ใช้ JS ตอน runtime เพราะง่ายกว่า · ของจริงต้องเป็น static ตอน build
> (SEO, ไม่กระพริบ, ทำงานแม้ JS ปิด)

`_template/skeleton-{th,us}.html` แก้แค่ **ถอดอีโมจิ** — รายงานใหม่จะได้ไม่ใส่กลับเข้ามา
ห้ามแก้โครง skeleton เป็นทรงใหม่ (ดู invariant §2)

**ราคาที่ยอมจ่าย:** `dist/` ต่างจาก `reports/` มากขึ้น — แต่ต่างอยู่แล้วตั้งแต่ style/engine/votebar/TA
เป็นของเดิมเพิ่มปริมาณ ไม่ใช่ประเภทใหม่

## 5. หน้าแรก

### 5.1 ดีไซน์ที่เลือก — ไทล์สี

- **หัวการ์ด = บล็อกสีแบรนด์** ชื่อย่อตัวใหญ่สีขาวบน `accentDark` (ปลอดภัยตาม §3.3)
  glow ใช้ `accent` ได้เพราะไม่มีตัวหนังสือทับ
- **แถบสเปกตรัม**บนหัวเว็บ ทำจากสีแบรนด์จริงเรียงตาม hue — บอกตัวตนเว็บว่า "หลายบริษัท แต่ละตัวมีตัวตน"
- **แถบสถิติ**: 908 รายงาน / 238 ไทย / 670 สหรัฐ / อัปเดตล่าสุด
- **หน้าเป็นโมโนโครม** (ดำ-เทา-ขาว) โดยตั้งใจ — ถ้าหน้าแรกมีสีของตัวเองจะตีกับสีการ์ด 908 สี
### 5.1.1 กฎอีโมจิหน้าแรก — "สื่อข้อมูล = เก็บ · ประดับ = ทิ้ง"

| จุด | ตัดสิน | เหตุผล |
|---|---|---|
| ชิปเรียง `👍 ไลก์` `👁 วิว` `🎯 MOS` `📈 Upside` … | **ทิ้ง** | มีข้อความกำกับอยู่แล้ว ไอคอนไม่เพิ่มข้อมูล |
| ธง 🇹🇭 / 🇺🇸 บนการ์ด | **เก็บ** | บอกตลาดได้ทันทีในที่ที่ไม่มีข้อความอื่นบอก |
| ไอคอนชิปจุดเด่น `.hl .hl-ic` (💎/💰/📈) | **ทิ้ง** | ชิปมีทั้งค่าและคำอธิบาย + แยกประเภทด้วยสีอยู่แล้ว ⇒ ซ้ำซ้อน |
| ตัวนับ `.cviews` (👁 👍 👎) | **เก็บ** | เป็น *ป้ายชื่อ* ของตัวเลข — ถ้าเอาออกเหลือ `0 · 0 · 0` อ่านไม่รู้เรื่อง |
| ปุ่มโหวตในรายงาน (`.votebar` 👍 👎) | **เก็บ** | เหตุผลเดียวกับข้างบน |

### 5.1.2 ★ สัญญาที่ห้ามผิด — gate ตรวจ markup การ์ดหน้าแรกตรง ๆ

`test/check-site.js:127` จับด้วย regex `<a class="card"[^>]*href="\./<SYM>\.html"` และอ่าน `data-*` ต่อ
⇒ การ์ดใหม่**ต้องคง**:

- `<a class="card"` — `class="card"` เป็น attribute **แรก** และสะกดตรงเป๊ะ
- `href="./<SYM>.html"`
- `data-market` (ใช้กรองไทย/สหรัฐ + gate เทียบกับ currency ของรายงาน)
- `data-mos` `data-upside` `data-pe` `data-yield` `data-roe` (ใช้เรียง + gate เทียบกับ stock-meta)

สีต่อการ์ดจึงต้องใส่เป็น inline style **หลัง** `class="card"` เช่น
`<a class="card" style="--c:#31a60d;--cd:#23760a" data-search="…" data-mos="12" … href="./ZTS.html">` ✅

### 5.2 View toggle (ไทล์ ⇄ ตาราง)

โหมดตารางคือ **CSS ชุดเดียวกันบน DOM เดิม** ไม่มี markup ใหม่:

- `.grid` ได้ class `is-table` → `.card` กลายเป็นแถว grid, `.cmetrics{display:contents}` ทำให้
  `.cm` 5 ตัวกลายเป็นคอลัมน์ที่ตรงกับหัวตารางพอดี
- `--cols` ประกาศบน `.grid` (ไม่ใช่ `.card`) เพื่อให้หัวตารางกับแถวใช้ค่าเดียวกัน
- ปุ่มสลับวางข้างชิปเรียง · จำค่าไว้ใน `localStorage`
- มือถือ (<900px) บังคับกลับเป็นการ์ดเสมอ — ตารางกว้างเกินจอ

**เหตุผลที่คุ้ม:** 908 รายการ · โหมดไทล์เห็น ~6 ตัว/จอ · โหมดตารางเห็น ~20 ตัว/จอ
และตัวเลข MOS/Upside/P/E/Yield/ROE เรียงเป็นคอลัมน์ ⇒ **เทียบข้ามหุ้นได้จริง**
(ของเดิมเทียบไม่ได้เพราะเลขลอยคนละตำแหน่งในแต่ละการ์ด)

### 5.2.1 สีแบรนด์ไปถึงการ์ดหน้าแรกยังไง

`reports.json` **ไม่มี** field สี (ตรวจแล้ว: `symbol/file/name/title/desc/updated/hash/metrics`)
mockup แก้ขัดด้วยการอ่านไฟล์รายงานซ้ำทั้ง 908 ไฟล์ — **ของจริงห้ามทำแบบนั้น**

**วิธีที่ถูก:** build อ่านรายงานทุกใบอยู่แล้วรอบหนึ่ง ⇒ เก็บ `theme.accent` / `theme.accentDark`
ใส่ array `reports` **ในหน่วยความจำ** ตอนนั้นเลย แล้วหน้าแรกหยิบไปใช้

- ❌ **ห้ามเพิ่ม field ลง `reports.json`** — เป็น artifact ที่ commit และ CLAUDE.md ระบุ "ห้ามแก้มือ"
  ทั้งยังมี consumer อื่นที่ยังไม่ได้ไล่ครบ ⇒ schema คงเดิม
- รายงานที่ไม่มี `theme.accent` → ใช้ `THEME_DEFAULTS` (การ์ดออกมาเป็นสีเทากลาง ไม่พัง)

### 5.3 ที่ไม่เปลี่ยน

ค้นหา · กรองตลาด · เรียง 7 แบบ · แบ่งหน้า · ตัวนับวิว/โหวต — logic เดิมทั้งหมด
(mockup พิสูจน์แล้วว่าใช้ได้ เพราะทำงานบน `dist/index.html` ของจริง)

## 7. นอกขอบเขต

- **Dark mode** — ต้อง derive สีมืด 908 ชุด + ตรวจ contrast ใหม่ทั้งหมด แยกเป็นงานต่างหาก
- **migrate markup 908 ไฟล์** — ยกเลิกแล้ว (§2)
- สลับลำดับ/เพิ่มลดส่วนในรายงาน — เจ้าของยืนยันว่า 8 ส่วนเดิมดีแล้ว
- metric ใหม่ / แหล่งข้อมูลใหม่

## 8. ความเสี่ยง

| ความเสี่ยง | รับมือ |
|---|---|
| CSS ใหม่ทำ gate 38 error ตก | ชื่อ class/id คงเดิมทุกตัว (§4.2) · รัน `npm run verify` ครบ 10 ขั้นก่อน push |
| หน้าแรกใหม่ทำ `check-site` ตก (regex จับ markup การ์ด) | คงสัญญา §5.1.2 · ไล่ `build-test.js` + `check-site.js` หา assertion ฝั่ง index **ก่อน**เริ่มเขียน ไม่ใช่ตอน verify ตก |
| สีแบรนด์บางตัวย้อมพื้นแล้วมืด/ขุ่น | gate §3.4 ตรวจ ink บน tint-bg ทุกใบ — ตก = build error |
| การ์ดสีจัด 908 ใบแล้วรก | หน้าแรกเป็นโมโนโครม สีจำกัดอยู่ในหัวการ์ด · มี view toggle ไปโหมดตารางที่สีน้อยลง |
| nav/อีโมจิ inject ตอน build แล้วเพี้ยนบางใบ | inject เป็น static string ตอน build ⇒ `npm run build` แล้วตรวจได้ก่อน push |
| `dist/` ห่างจาก `reports/` มากขึ้น | ยอมรับ — เป็นรูปแบบเดิมที่ใช้อยู่แล้ว 4 อย่าง |

## 9. เกณฑ์ว่าเสร็จ

1. `npm run verify` ผ่านครบ 10 ขั้น (รวม gate contrast ใหม่)
2. `npm run test:self` ผ่าน (มีเคส contrast ใหม่)
3. เปิดดูจริงบน preview: หน้าแรก (ทั้ง 2 โหมด) + รายงานไทย + รายงาน US + ที่ ~390px
4. รายงานสุ่ม ≥5 ใบที่สีแบรนด์ต่างกันมาก — อ่านออกหมด ไม่มีจุดสีตีกัน
5. **เจ้าของดูของจริงแล้วอนุมัติ → ค่อย push** (งานนี้แตะ build.js/_template ⇒ อยู่นอกขอบเขต auto-push ตาม CLAUDE.md §5)
