## คำตัดสินของเจ้าของ (22 ก.ย. 2569) — กฎ UPDATE-LIGHT / UPDATE FULL ใหม่ (งาน W11)
1. **LIGHT** ก็ต่อเมื่อ **ไม่มีงบการเงินรายไตรมาส/รายปีออกหลังวันที่ footer "ข้อมูล ณ" ของรายงานเดิม** · เหตุการณ์อื่น (8-K, ลด guidance, ควบรวม) ไม่นับเป็น "งบ" (ช่องว่างที่รู้: GAP-008)
2. **FULL** เมื่อมีงบใหม่ · หรือราคาขยับ **>30% เทียบวันก่อนหน้า** (รายวัน ไม่ใช่สะสม) · หรือ split / ตัดปันผล / not-on-exchange · **ไม่รู้วันที่งบ = FULL**
3. EPS screen (เกณฑ์ ±2% เดิม) **ลดเหลือคำเตือน** ไม่ใช่เกณฑ์เลือกโหมด
4. ขอบเขตการแก้ = ตัวจัดคิว (triage.js) + prep.js + SKILL + เอกสาร — **ไม่แตะค่าคงที่ของ cron ราคา** (SUSPECT_FREEZE ยังเป็น 0.25) · ขอบเขตที่สั่งแล้ว = W11 · W1 และ W9 เสนอเพิ่มตามคำวินิจฉัยของ advisor (รออนุมัติ) · W2–W8 ไม่ต้องแก้ตอนนี้

## เกณฑ์คำวินิจฉัย
**ต้องแก้ตอนนี้** = อาจทำให้ตัวเลขผิดถูกเผยแพร่ในรายงาน หรือทำให้คิวพังในการใช้งานปกติ หรือเจ้าของสั่ง — และแก้แบบกำหนดผลได้/ทดสอบได้ · **ทำเมื่อพบซ้ำ** = ยังไม่คุ้ม แก้เมื่อเข้าเงื่อนไขที่ระบุ · **ไม่แก้** = เสีย token/turn อย่างเดียว เฉพาะแคมเปญ ทำอัตโนมัติไม่ได้ หรือเป็นสภาพแวดล้อม · **รอเจ้าของ** = เป็นเรื่องนโยบาย ไม่ใช่บั๊ก · **ไม่ต้องแก้ (ปิดแล้ว)** = แก้จบแล้วหรือเป็นบันทึกข้อเท็จจริง

## ความหมายของสถานะ
ปิดแล้ว = แก้จบหรือไม่ต้องแก้ · บรรเทา = มีทางเลี่ยงแต่ต้นเหตุยังอยู่ · เปิด = ยังไม่แก้ · เลื่อน = ตัดสินใจไม่แก้ตอนนี้ (เหตุผลในคอลัมน์งาน) · รอเจ้าของ = ต้องการคำตัดสิน
