## เกณฑ์ "ต้องแก้"
อย่างใดอย่างหนึ่ง: (1) อาจทำให้**ตัวเลขผิดถูกเผยแพร่**ในรายงาน (2) ทำให้**คิวพังในการใช้งานปกติ**ทีละตัว (3) **เจ้าของสั่ง** — และแก้ได้แบบกำหนดผลแน่นอนและทดสอบได้ · ถ้าแค่เสีย token/เสียเวลา, เกิดเฉพาะแคมเปญ, ทำอัตโนมัติไม่ได้ หรือเป็นเรื่องนโยบาย = **ไม่ใช่งานแก้บั๊ก**

## รายละเอียดแต่ละงาน

### W11 — กฎ UPDATE-LIGHT / FULL (เจ้าของตัดสินแล้ว)
**กฎใหม่:** LIGHT ก็ต่อเมื่อไม่มีงบ **รายไตรมาส/รายปี** ออกหลังวัน footer ของใบเดิม · FULL เมื่อ มีงบใหม่ / ราคาขยับ **>30% เทียบวันก่อนหน้า** / split / ตัดปันผล / หุ้นตาย / **ไม่รู้วันที่งบ** · EPS screen (±2% เดิม) → คำเตือน ไม่ใช่เกณฑ์เลือกโหมด
**รวมในงานนี้ (แก้แบบเล็ก ๆ ไฟล์เดียวกัน):** BUG-026 (auto-mode) · BUG-008 (note "ยังไม่ pre-patch") · BUG-001 (หุ้นที่ vendor EPS ≤0 ⇒ ยาก) · BUG-017 (SKILL: "$" → สกุลเงินจริง) · BUG-029 (ประโยคใน SKILL: LIGHT ต้องตั้ง footer + แปลงตัวเลขผูกราคาเป็น token) · ข้อความคำเตือน EPS แสดงทั้งสองฐาน
**ไฟล์:** `tools/queue/triage.js` (กลับด้าน `earnings-after-analysis` → FULL + เกณฑ์ drift รายวัน 15–30% = LIGHT, >30% = FULL) · `tools/queue/prep.js` · `tools/queue/preflight.js` · `.claude/skills/stock-analyzer/SKILL.md` (STEP 5C ข้อ 2) · `.claude/skills/stock-controller/SKILL.md` · `test/queue-test.js` · `docs/decisions.md` · generated docs
**ไม่แตะ:** ค่าคงที่ของ cron ราคา (`SUSPECT_FREEZE` ยังเป็น 0.25) · รายงานใน `reports/`
**การหาวันที่งบ (ทำให้เล็กลง):** ใช้ `tools/earnings-calendar.js` ที่มีอยู่แล้ว (Yahoo, ครอบคลุม 719/908 = 79% — `docs/open-items.md` #24, #29) + ไม่รู้ = FULL + เส้นตายงบ SET สำหรับหุ้นไทย (ต้องตรวจกรอบวันบน set.or.th ก่อนใส่) · SEC submissions เป็นตัวเลือกเสริมสำหรับ 21% ที่ไม่มีวันที่ — **agent ต้องอ่าน `earnings-calendar.js` และ open-items #24/#29 ก่อนเริ่ม**
**ความคาดหวังที่ตรงไปตรงมา:** การรันทั้ง 908 ใบแบบแคมเปญนี้ประหยัดได้น้อย (เกือบทุกใบมีงบ Q2 ออกแล้ว) ผลจริงอยู่ที่คิวใช้งานปกติระหว่างไตรมาส
**เงื่อนไขผ่าน:** `npm run verify` เขียว · queue-test 7 กรณี (มีงบใหม่=FULL · ไม่มีงบ+ขยับ 10%/20%=LIGHT · ขยับ 35%=FULL · เลยเส้นตาย SET=FULL · ไม่รู้=FULL · EPS ต่าง 40% ไม่มีงบ=LIGHT+เตือน) · จำนวน E/W ตรง baseline (งานนี้ไม่แตะรายงาน) · `git diff --name-only` มีแต่ไฟล์ที่ระบุ
